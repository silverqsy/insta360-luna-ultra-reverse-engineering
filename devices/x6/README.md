# Insta360 X6 v0.8.825：本地 root 命令验证

[项目主页](https://github.com/silverqsy/insta360-x6-research) · [English](README.en.md) · [来源与许可](ATTRIBUTION.md)

> **X6 专用入口：只使用本目录的 Python 工具，在电脑上运行。不要在 X6 上运行仓库根目录的 `scripts/install.sh`、`scripts/uninstall.sh` 或 `device/enable-usb-adb.sh`，也不要安装任何 `luna-*.service`。** 这些上游脚本针对 Luna Ultra，会更改 ADB 服务或 USB 配置，未在 X6 上验证。
>
> 本目录于 2026-10-24 加入 X6 适配。上游项目、作者和协议来源见 [ATTRIBUTION.md](ATTRIBUTION.md)；采用仓库根目录的 [Apache-2.0 许可证](../../LICENSE)。

仅适用于自己拥有、已获授权操作的 X6，**固件版本必须为 v0.8.825**。此前在一台该版本设备上验证了 GUI 调试入口：`id` 返回 `uid=0(root)`，正常重启后入口仍可用。此结论不适用于 v1.0.20、v1.2.36，也不表示官方升级后会保留访问。

本目录是该方法的独立 Python 实现，不需要 SDK。公开版已在全新 Python 虚拟环境中通过单元测试，以及模拟相机的 `pair → probe → run` 流程和错误场景测试。模拟测试使用本机 TCP、合成身份和模拟 root 输出，不是新增实机验证；公开版尚未在另一台相机上完整验证。工具不安装服务、不刷固件，不提供持久 root 或救砖保证。

## 准备

- macOS 或 Linux 终端；Python 3.10 或更新版本，无第三方 Python 依赖，无需 `pip install`。本次干净环境检查使用 macOS / Python 3.13。
- 本文记录的是未激活新机的首次进入流程：保持相机在首次开机、提示连接官方 App 的界面，直接利用此时已开启的 Wi-Fi。**不要连接官方 App，也不要完成官方激活，以免进入强制升级流程而失去旧固件入口。**
- 不需要先进入 Camera Info 或正常拍摄界面。`pair` 会先通过只读查询核对机型和固件；只有 v0.8.825 才会继续。工具不修改激活状态，不触发固件升级。
- 电脑直接连接首次开机时目标相机开启的 Wi-Fi，电脑应获得 `192.168.42.*` 地址，相机为 `192.168.42.1`。使用机主控制的直连网络；若热点不可见，停止，不通过连接官方 App 来解决。
- 允许 Python 接收来自相机的本地 TCP 回连，回连使用临时端口。相机控制端口为 6666，GUI 调试端口为 23456；工具只连接上述固定地址，不扫描网络。

连接授权是本工具的操作前置，不代表旧 GUI 调试入口本身具有同样认证。该传输不加密。

取得此适配分支后，**在仓库根目录打开交互式终端**，执行下面的命令进入 `devices/x6`。后续 `pair`、`probe`、`run` 命令均在这个目录运行，不需要电脑端 `sudo`；也不需要把仓库复制到相机。以下测试不会连接相机：

```sh
cd devices/x6
python3 --version
python3 -m unittest -v
```

测试应全部通过。如果系统找不到 `python3`，先安装 Python 3.10 或更新版本，再继续。

## 1. 配对

```sh
python3 x6_root.py pair
```

按提示输入这台相机机身或对应原包装标签上的完整序列号，用于核对当前目标；输入不会回显。不需要激活或进入相机菜单来读取它。若相机弹出连接确认，在 60 秒内点“允许”。应看到 `Paired locally`。

工具在**当前目录**生成 `.x6-owner-state.json`，保存客户端标识和序列号摘要，创建权限为仅本机用户可读写。保留此文件供后续命令使用，不上传或分享。配对是普通连接授权，不是官方产品激活。已有配对文件时不重复执行 `pair`。

## 2. 验证 root

```sh
python3 x6_root.py probe
```

成功结果为：

```text
Verified: uid=0(root)
```

工具执行 `/usr/bin/id`，核对 root 身份、随机回传标记和命令完成状态。`Pack success`、开放端口或设备出现在列表中不能替代此结果。执行前核对版本、同一设备和连接授权，执行后再次核对身份。

## 3. 运行短命令

下面先创建 UTF-8 命令文件，再执行。`EOF` 是终端输入块的结束标记，不属于相机命令：

```sh
cat > command.txt <<'EOF'
/usr/bin/id
EOF
python3 x6_root.py run --command-file command.txt
```

应先看到 `Verified: uid=0(root)`，再看到命令自己的 `uid=0(root)` 输出。命令在相机上运行。`run` 每次先独立检查 root，再执行命令文件。

工具只回传标准输出，不回传标准错误，也不是交互式终端。每次回传最多等待约 20 秒，标准输出上限为 64 KiB；过长命令会在联网前被拒绝。非零退出状态、缺少完成标记或截断回传均报错并返回非零退出码。**超时只结束电脑端等待，不保证停止相机上的命令；仅使用短时命令，超时后不要盲目重复有副作用的操作。** 前面的 root 成功行不表示后面的自定义命令成功。

如需验证可丢弃文件的写读删，用以下内容替换命令文件并运行。它只创建一个随机命名的临时文件，退出时清理：

```sh
cat > command.txt <<'EOF'
p=$(/bin/busybox mktemp /tmp/x6-check.XXXXXX) || exit 1
trap 'rm -f "$p"' EXIT
printf 'owner-check\n' > "$p" && [ "$(cat "$p")" = owner-check ] && rm -f "$p" && printf 'write/read/delete OK\n'
EOF
python3 x6_root.py run --command-file command.txt
```

应出现 `write/read/delete OK`。这验证的是临时目录写入；root 不表示系统分区已可写，也不证明升级后仍可修改固件。

## 重启后复核

确认没有正在进行的升级或待安装升级包，再用相机普通电源操作重启。重新连接 Wi-Fi，在同一工作目录保留配对文件，重新运行 `probe` 和上述临时文件测试。失败就停止，不通过升级、降级或切槽来修复入口。仅凭本工具成功不能证明恢复路径可用。

## 无结果时

- 连接超时：确认电脑仍连着相机 Wi-Fi，相机没有自动关闭热点。
- 回传超时：检查防火墙是否允许 Python 接收相机的回连；相机仅返回 `Pack success` 不算执行成功。
- 版本或设备不匹配：停止，核对机身或对应包装标签、当前连接的热点；工具会拒绝不匹配的设备或固件，不改脚本跳过检查，也不通过官方激活或升级来解决。
- `Run pair first`：确认当前目录正确，且该目录有本机保存的配对文件。
- 未授权：把工具和测试文件复制到新的工作目录，重新 `pair` 并在相机确认；旧配对文件留在原目录。
- 配对文件损坏：不要修改其中的身份摘要；使用新工作目录重新配对。
- 非零退出状态或完成标记错误：本次命令未被确认成功。先核实命令和相机状态；不要仅凭 root 成功行判断。
- 未确认 `uid=0` 或端口拒绝：当前条件下没有验证成功，不据此刷入其他固件。
